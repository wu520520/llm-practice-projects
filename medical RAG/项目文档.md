## 一、项目概述

### 1.1 做了什么

构建一个**医疗健康领域的智能问答助手**：用户用自然语言提问（如"糖尿病有哪些症状？"），系统从本地医疗知识库中检索相关文档，将文档作为上下文交给大语言模型（LLM）生成专业回答。

这就是 **RAG（Retrieval-Augmented Generation，检索增强生成）** 的完整实现。

### 1.2 为什么需要 RAG

| 问题 | 纯 LLM | RAG |
|------|--------|-----|
| 知识时效性 | 训练数据截止后无法更新 | 随时更新知识库即可 |
| 领域专业性 | 通用知识，缺乏医疗深度 | 基于专业医疗数据回答 |
| 幻觉（编造事实） | 经常发生 | 依据检索到的资料作答，可追溯 |
| 数据隐私 | 数据须送入模型训练 | 知识库本地存储，不上传 |

### 1.3 技术栈

| 技术 | 用途 | 对应知识领域 |
|------|------|-------------|
| PyTorch | 深度学习推理引擎 | KA#1 |
| pandas | 数据加载与清洗 | KA#2 |
| sentence-transformers | 文本向量化（BGE-M3） | KA#3/#4 |
| FAISS | 向量索引与余弦相似度检索 | KA#5 |
| Transformers (HuggingFace) | 加载 Qwen3 生成模型 | KA#4 |
| LangChain | Prompt 模板与消息抽象 | KA#3 |
| FastAPI | Web 服务与接口 | KA#6 |

### 4.2 data_loader.py — 数据加载与清洗

**职责**：加载 CSV、清洗文本、构建结构化文档。

#### 4.2.1 编码自动探测

```python
def detect_encoding(path, try_encodings=("utf-8-sig", "utf-8", "gb18030", "gbk")):
    for encoding in try_encodings:
        try:
            with open(path, "r", encoding=encoding) as f:
                f.read(4096)
            return encoding
        except UnicodeDecodeError:
            continue
    return "gb18030"
```

**为什么需要**：Windows 中文环境下的 CSV 通常是 GBK 编码，直接用 UTF-8 读取会乱码。这里依次尝试常见编码，保证兼容。

### 4.3 embeddings.py — 文本嵌入模型

**职责**：用 BGE-M3 将文本编码为 1024 维稠密向量。

```python
class BGEEmbedder:
    """线程安全单例，进程内只加载一次模型"""
    
    def encode(self, texts, normalize=True):
        # normalize=True: L2 归一化，使内积 = 余弦相似度
        embeddings = self._model.encode(texts, normalize_embeddings=True)
        return embeddings  # shape: (n, 1024)
```

**核心概念**：

**文本嵌入（Embedding）** 是什么？

将文本映射为一个固定长度的浮点数向量（如 1024 维），使**语义相近的文本在向量空间中距离也近**。

```
"糖尿病有哪些症状？"  →  [0.12, -0.34, 0.56, ..., 0.78]  (1024 个数)
"糖尿病的典型症状"    →  [0.11, -0.33, 0.55, ..., 0.77]  (非常接近)
"怎么做红烧肉"       →  [0.45, 0.23, -0.67, ..., 0.03]  (完全不同)
```

**为什么选 BGE-M3**：
- 支持中英文
- 1024 维，兼顾效果与效率
- 多语言、多粒度检索能力强
- 开源免费，可本地部署

**单例模式**：模型加载耗时数秒，用 `__new__` + 线程锁确保只加载一次。

### 4.4 vector_store.py — FAISS 向量索引

**职责**：构建、持久化、加载 FAISS 索引。

#### 4.4.1 为什么用内积索引（IndexFlatIP）做余弦检索

```python
# 向量先 L2 归一化 → ||v|| = 1
# 此时内积 = 余弦相似度：a·b = cos(θ)
index = faiss.IndexFlatIP(1024)  # 内积索引
index.add(normalized_vectors)    # 添加归一化后的向量
```

**数学原理**：
```
余弦相似度 = (a · b) / (||a|| × ||b||)
当 ||a|| = ||b|| = 1 时 → 余弦相似度 = a · b = 内积
```

所以：**L2 归一化 + 内积索引 = 余弦相似度检索**，分数范围 [-1, 1]，越大越相关。

#### 4.4.2 持久化的坑

```python
# FAISS C++ 的 write_index 在 Windows 下无法处理含中文的路径
# 解决方案：先序列化为字节数组，再用 Python 写文件

index_array = np.asarray(faiss.serialize_index(self.index), dtype="uint8")
with open(index_path, "wb") as f:
    f.write(index_array.tobytes())

# 加载时反过来
with open(index_path, "rb") as f:
    index_array = np.frombuffer(f.read(), dtype="uint8")
index = faiss.deserialize_index(index_array)
```

#### 4.4.3 索引与文档的对应关系

```
FAISS 向量行 0  ←→  medical_docs.json 第 0 条  ←→  疾病：糖尿病
FAISS 向量行 1  ←→  medical_docs.json 第 1 条  ←→  疾病：高血压
...
```

检索时 FAISS 返回行号，用行号从 `self.documents` 列表取对应文档内容。

### 4.5 retriever.py — 检索模块

**职责**：接收用户问题 → 编码为向量 → FAISS 检索 → 返回 Top-K 文档。

```python
class MedicalRetriever:
    def retrieve(self, question, top_k=3):
        # 1. 用户问题 → BGE-M3 编码为 1024 维向量
        query_vector = self.embedder.encode(question)
        # 2. FAISS 内积检索 Top-K
        hits = self.vector_store.search(query_vector, top_k=top_k)
        # 3. 封装为 RetrievedDoc 返回
        return [RetrievedDoc(title=..., content=..., score=..., metadata=...) 
                for doc, score in hits]
```

**首次运行自动建库**：

```python
@classmethod
def from_storage(cls):
    if FAISSVectorStore.exists():
        store = FAISSVectorStore.load()      # 已有索引 → 直接加载
    else:
        dataframe = load_and_clean()         # 无索引 → 清洗数据
        documents = build_documents(dataframe)
        store = FAISSVectorStore.build(documents)  # 向量化建库
        store.save()                          # 持久化
    return cls(store)
```

### 4.6 llm.py — 生成模型

**职责**：接收消息列表，生成回复文本。支持本地/在线双模式。

#### 4.6.1 本地模式（LocalQwenLLM）

```python
# 用 PyTorch + Transformers 加载 Qwen3-0.6B
self.tokenizer = AutoTokenizer.from_pretrained(model_path)
self.model = AutoModelForCausalLM.from_pretrained(model_path, dtype=dtype)
```

**关键设计**：
1. **关闭 thinking 模式**：Qwen3 默认输出推理过程（`...`），RAG 场景需要直接答案
2. **贪心解码**：温度设为 0 时 `do_sample=False`，输出确定性更高
3. **repetition_penalty=1.05**：小模型容易重复，加惩罚项缓解
4. **strip_think_tags**：兜底清理残留的思考标签

#### 4.6.2 API 模式（OpenAICompatibleLLM）

通过 OpenAI SDK 调用在线大模型（通义/DeepSeek/硅基流动），接口兼容、切换零成本。

#### 4.6.3 工厂模式

```python
def get_llm(mode=None):
    if mode == "api":
        return OpenAICompatibleLLM()
    return LocalQwenLLM()  # 默认本地
```

### 4.7 memory.py — 短期对话记忆

**职责**：按会话（session_id）保存最近若干轮问答，注入生成 Prompt。

```python
class ConversationMemory:
    def __init__(self, max_turns=3):
        self._store = {}  # {session_id: deque(maxlen=6)}
    
    def add_turn(self, session_id, question, answer):
        # 追加一轮问答，超出窗口自动丢弃最旧的
        history.append({"role": "user", "content": question})
        history.append({"role": "assistant", "content": answer})
```

**为什么用 deque**：
- `maxlen` 自动丢弃旧消息，无需手动管理
- 线程安全（配合 `threading.Lock`），FastAPI 并发安全

**多轮对话示例**：
```
第 1 轮：用户 "糖尿病有哪些症状？"     → 回答 "多饮多尿..."
第 2 轮：用户 "那应该去哪个科室？"      → 历史注入后，模型知道"那"指代糖尿病
```

### 4.8 service.py — RAG 业务编排

**这是最核心的模块**，串联检索、记忆、生成。

#### 4.8.1 Prompt 设计

```python
SYSTEM_PROMPT = "你是医疗问答助手，只能依据【参考资料】回答，不得编造..."

QA_PROMPT = ChatPromptTemplate.from_messages([
    ("system", SYSTEM_PROMPT),                    # 系统约束
    MessagesPlaceholder("history"),                 # 多轮对话历史
    ("human", "【参考资料】\n{context}\n\n【用户问题】\n{question}"),  # 资料+问题
])
```

**为什么这样设计**：
- 系统提示约束模型"只依据资料回答"，抑制幻觉
- 历史占位符让模型理解上下文指代
- 资料与问题同在一条 human 消息中，让模型直接关联

#### 4.8.2 多轮检索查询扩展

```python
# 问题："那应该去什么药？" 单独检索会漏检
# 解决：用最近一轮用户问题扩展检索语句
retrieval_query = question  # "那应该去什么药？"
if history:
    last_user_question = ...  # "糖尿病有哪些症状？"
    retrieval_query = f"{last_user_question} {question}"
    # → "糖尿病有哪些症状？ 那应该去什么药？" → 正确命中糖尿病文档
```

**关键**：扩展仅用于检索，不进入生成 Prompt（生成 Prompt 中仍是原始问题）。

#### 4.8.3 双重相似度过滤

```python
# 绝对阈值：Top-1 分数 < 0.55 → 知识库无相关资料 → 拒答
# 相对分差：与 Top-1 分差 > 0.12 → 弱相关噪声 → 不进入上下文
top_score = retrieved[0].score  # 如 0.76
score_cutoff = max(0.55, 0.76 - 0.12)  # = 0.64
effective_docs = [doc for doc in retrieved if doc.score >= 0.64]
```

**为什么需要双重过滤**：
- 只用绝对阈值：Top-3 中 0.52 的文档会混入上下文，干扰生成
- 只用相对分差：知识库外问题（最高 0.44）仍会尝试回答
- 双重过滤既拦截域外问题，又剔除 Top-K 中的噪声

#### 4.8.4 懒加载设计

```python
@property
def llm(self):
    if self._llm is None:
        self._llm = get_llm(self.llm_mode)  # 首次问答时才加载
    return self._llm
```

**为什么**：模型加载耗时数秒到数十秒。服务启动时只加载检索器（快），生成模型在第一次问答时才加载，缩短启动等待。

## 六、关键设计决策与踩坑记录

### 6.1 FAISS 中文路径问题

**现象**：`faiss.write_index()` 报错 "could not open file for writing"。

**原因**：FAISS 底层是 C++ 实现，在 Windows 上无法处理含中文字符的文件路径。

**解决**：先 `faiss.serialize_index()` 序列化为 numpy 字节数组，再用 Python 原生 `open()` 写文件。

### 6.2 Qwen3 thinking 模式

**现象**：模型输出大段推理过程而非直接答案，耗尽 token 预算。

**原因**：Qwen3 默认开启 thinking 模式，会先输出 `...` 推理链。

**解决**：`apply_chat_template(enable_thinking=False)` 关闭思考模式。

### 6.3 多轮对话检索漏检

**现象**：用户追问"那该用什么药"时，检索结果与上一轮无关。

**原因**：追问常含指代词（"那"），单独编码无法关联上文主题。

**解决**：用最近一轮用户问题扩展检索语句（仅用于检索，不进入生成 Prompt）。

### 6.4 小模型幻觉控制

**现象**：知识库无相关内容时，小模型仍自由发挥编造答案。

**解决**：双重相似度过滤（绝对阈值 0.55 + 相对分差 0.12），不达标直接返回兜底提示。

## 八、扩展方向

1. **扩充知识库**：在 `medical_qa.csv` 中追加更多疾病数据，运行 `python build_index.py --rebuild` 即可
